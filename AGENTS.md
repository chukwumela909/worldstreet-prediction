# Project rules

Prediction market on live Polymarket and Bayse data, styled 1:1 on the WorldStreet prediction marketplace design (tokens v5.1). See README.md; docs/polymarket-recon.md covers the original Polymarket clone the data layer grew out of.

- **Components consume ONLY semantic tokens** (`bg-page`, `bg-surface`, `bg-sunken`, `text-primary`, `text-secondary`, `bg-yes-tint`, `text-yes`, `bg-accent`, `text-on-accent`, `text-accent-ink`, `text-domain`, `rounded-sm|md|xl`, `shadow-card`, ...) — never raw hex, never Tailwind default palette (it is disabled in app/globals.css).
- Token system lives in app/globals.css: Layer 1 primitives (`--neutral-*`, `--brand-*`, ...) → Layer 2 semantic (`--bg-page`, `--yes`, ...) → Tailwind `@theme inline` mapping. Rebrand = repoint primitives; components must never change.
- **Gold fills vs gold text.** The accent is WorldStreet gold (`#e2b43f`). A solid gold surface takes `text-on-accent` (near-black) — never `text-white`, which is about 1.9:1. Gold *copy or icons* use `text-accent-ink`, not `text-accent`: same gold in dark, a deep gold stop in light, where `#e2b43f` on near-white is under 2:1.
- Dark is the default theme (`html[data-theme="dark"]`); light overrides in `[data-theme="light"]`. Both carry the reference palette (dark: the prediction-shell surfaces `#0f0f0f` page / `#141414` card / `#222222` raised). Every ladder dark defines is pinned in light too — add a primitive to dark and you must decide what light does with it.
- Type: Instrument Sans + IBM Plex Mono. Tailwind's text scale is remapped to the reference's sizes — `text-xs` 12 (caption), `text-sm` 13.5 (UI, the body default), `text-base` 15 (body), `text-xl` 19 (heading), `text-3xl` 31 (display).
- Radius: buttons `rounded-sm` and inputs/chips `rounded-md` are 8px, cards `rounded-xl` are 12px. Filled buttons add the `pressable` utility (sheen + 1px press).
- **Caution is its own colour too.** Risk flags and "watch" states use `text-warning` / `bg-warning-tint` (the reference's feedback.warning yellow); danger uses `text-no` / `bg-no-tint`. Never the gold accent for a warning — gold is the brand and the buy action. The admin desk's flag colours all come from `FLAG_TONE` in components/admin/risk-flags.tsx.
- **Live is its own colour.** A game in progress (sports LIVE frame and label, live rail games, the "LIVE · N" count) uses `text-live` / `border-live` / `var(--live)` — the reference's predict purple. Don't reach for `text-domain` for it: the domain accent only marks which product you're in and never carries meaning.
- Buy-button state model (outcome rows and quote pills): rest = `text-yes bg-yes-tint` / selected = `text-white bg-yes-solid` (same for no). The bet slip's Yes/No answer pills are the exception, as the reference draws them: plain on a `bg-element-2` track at rest, `bg-accent text-on-accent` when picked, either side (SideToggle).
- Outcome quotes use components/market/outcome-quote.tsx. Board surfaces (cards, featured market): a `ProbabilityBar` in the outcome's tone (`YES_TONE`/`NO_TONE` for binary sides, else `outcomeTone(i)`, matching the chart's `--chart-n` line) and a `QuotePill` outlined in gold (`PILL_TONE`) — the bar identifies the outcome, the pill is the buy action. The market page's Yes/No buttons use `QuotePill variant="side"`: neutral outline, green/red text.
- **The Local book always trades; the international book only when the API says so — and every price carries the house's margin.** Every trade is against WorldStreet in naira credit. The pricing is the API's, published at `GET /v1/markets/pricing` (`internationalTrading`, `polymarketSpreadBps`, `localSpreadBps`, `autoSpreadStepKobo`, `minStakeKobo`, `maxStakeKobo`); the root layout reads it through lib/book-pricing.ts (cached ~60s) and hands it down via `<BookPricingProvider>`. **Base margin, by source:** Bayse markets add `localSpreadBps`; our own (`source: "worldstreet"`) add 0 — desk-priced, the margin is already in; international (Polymarket) add `polymarketSpreadBps`, and only while `internationalTrading` is on. **Auto-rise:** on the side of a market where the house stands to lose, the API raises the price 1 point for every `autoSpreadStepKobo` it stands to lose (0 = off), with no cap — it grows with the bets until the quote meets the 9900 ceiling, and the market's loss limit stops new bets regardless; the quiet side never goes below its base. The API computes the rise per outcome — the web never does — and publishes it at `GET /v1/markets/rises?marketIds=<id>,<id>` (≤ 50 ids, keyed by market id then `outcomeIds` entry; only sides with a rise; 404 = none). It's read through `useMarketRises` (lib/use-market-rises.ts, one shared ~15s poller) in the bet slip and the market page's outcome rows only — never cards, lists or sports cards, which show the base price. **The quote** (lib/book.ts), with raw = `Math.round(p × 10000)` kobo from the outcome's decimal price: raw ≤ 0 or ≥ 10000 → 0 (not sold); base + rise = 0 → raw; raw ≥ 9900 → 0 (no room for a margin); else `min(raw + base + rise, 9900)`. Pricing null — no `NEXT_PUBLIC_API_URL`, an older API that 404s, any non-2xx — quotes Local markets raw with no rise (never a margin the API might not charge), and an API without the newer fields reads them as 0. International on: Polymarket markets trade like Local ones (pills "Buy Yes ₦63.00", bet slip live, Review → Confirm → receipt, outcomes named by their CLOB token ids as `outcomeIds`). Off — the switch off or pricing null — they are display-only mirrors: no quote on our book (`quoteKobo` → 0), payout multiples read off Polymarket's price, pills "Yes 60¢" with no "Buy", and the bet slip shows prices in ¢ with the amount locked and "Trading opens soon" — nothing can be submitted. Spreads, the auto-rise, stake limits and exposure are set by an admin on the API (admin Settings), never in the web app: no constant or env var for them here. `useQuote()` (components/book-pricing.tsx → lib/book.ts) is the only price path — every quote, payout multiple and stake limit a buyer sees comes from it, with the rise passed as its third argument where it's read — and "can this be bought here" is `isLocalBook(event) || useQuote().international`, never `isLocalBook` alone. The API charges the same rule on every order (services/api/src/trading/margin.ts) and answers PRICE_MOVED when a quote drifted.
- **Every response carries a Content-Security-Policy** (next.config.ts): scripts only from our origin and Clerk, data only to our origin, the API (`NEXT_PUBLIC_API_URL`) and Clerk, no framing. A new third-party script, iframe or browser-side fetch to another host is blocked until its host is added there. Inline scripts stay allowed — nonces would force per-request rendering and break the navigation speed rules below.
- Content width is `max-w-[1400px]` with `px-4 sm:px-6` gutters — header, footer and every page share it.
- **Navigation speed rules.** The header lives in the root layout (via `SiteChrome`) — pages never render `SiteHeader`, so it stays mounted while only the page swaps. Every dynamic route has a `loading.tsx` (skeletons in components/skeletons.tsx), which is what lets links prefetch an instant state. Pages don't await data at the top: each slow part sits in its own `<Suspense>`, keyed by the view when the view is a search param (home tabs), so a switch shows its skeleton at once. Home tabs warm each other's feeds with `after()`, and `getEventForPage` reuses events from recent lists. Measure on `next build` + `next start`, never dev.
- /tokens is the live token reference sheet.
